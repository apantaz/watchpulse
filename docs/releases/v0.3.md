# WatchPulse v0.3 — dbt Serving Catalog

Released: 2026-08-21

## Outcome

WatchPulse can rebuild a documented, tested, and locally queryable serving
catalog from its append-only source data without placing upstream APIs in the
user request path.

## Delivered

- a complete dbt-duckdb project under `warehouse`;
- materialized staging models for TMDB discovery and streaming lifecycle data;
- intermediate canonical content, lifecycle event, current availability, and
  upcoming availability models;
- normalized content, genre, provider mapping, availability, and event marts;
- `catalog_availability`, with TMDB-preferred metadata and streaming-source
  fallback metadata for upcoming titles;
- version-controlled provider and bootstrap genre reference seeds;
- freshness metadata for UI and operational consumers;
- atomic candidate build, validation, and serving-database publication;
- dbt model, table, and column documentation plus schema-level quality tests.

## Validation

- The atomic warehouse publication passed all 193 dbt checks with zero errors.
- The published database reopened independently and contained 190 catalog rows:
  160 current and 30 upcoming, across four providers in Greece.
- Its normalized marts contained 523 content rows, 391 content-genre rows, and
  385 historical streaming events.
- Current and upcoming states do not overlap, and all state invariants passed.
- Nine retained records demonstrate that content release date and provider
  availability date are stored as separate concepts.
- All 38 Python tests pass with 68.63% coverage, above the 65% project gate.
- Ruff, Python compilation, dbt dependency resolution, debug, and parse pass.

## Known limitations

- Retained development data currently covers Greece and four launch providers.
- The genre seed is a bootstrap reference; ADR-015 defines future scheduled
  TMDB genre ingestion, change detection, and unknown-genre alerts.
- Runtime and richer title metadata remain nullable until optional enrichment.
- The initial lifecycle policy ingests `new` and `upcoming`; temporary stale
  current availability remains an accepted first-release limitation.
- The serving database is published locally. Durable deployment and scheduling
  arrive in a later version.
- No backend discovery API or frontend is included yet.

## Next version

v0.4 adds a read-only backend discovery API with parameterized global filters,
shared section queries, content details, and catalog freshness responses.
