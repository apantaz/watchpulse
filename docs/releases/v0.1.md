# WatchPulse v0.1 — Foundation

Released: 2026-08-17

## Outcome

WatchPulse can now perform a bounded, region/provider-aware TMDB catalog seed,
preserve raw responses locally, display a readable catalog sample, and record
pipeline execution metadata in DuckDB.

## Delivered

- Python project metadata and dependency management through `pyproject.toml`;
- optional pyenv and standard virtual-environment setup;
- environment-backed configuration with validated regions and discovery windows;
- source-independent content and provider models;
- retrying, rate-limited HTTP client with request counting;
- TMDB subscription discovery for movies and TV;
- full TMDB metadata and watch-provider enrichment;
- immutable, partitioned raw Parquet writes;
- DuckDB `pipeline_runs` observability with sanitized failure messages;
- local catalog inspection command;
- pull-request/push CI and bounded manual-ingestion workflow;
- local protected-branch, Ruff, secret-detection, and pre-push pytest hooks;
- architecture, data model, ADR, and version roadmap documentation.

## Validation

- Ruff checks pass.
- 16 offline tests pass.
- Python compilation passes.
- Live Greece smoke ingestion completed successfully.
- Live run recorded 310 API requests and 310 raw records.
- Local inspection returned provider-aware movie and TV results.

## Known limitations

- Catalog content remains in raw Parquet rather than normalized DuckDB tables.
- TMDB provides the current catalog seed but not authoritative streaming
  lifecycle history.
- Added, removed, expiring, and upcoming lifecycle events are deferred to v0.2.
- dbt serving models, backend filters, and frontend are not implemented yet.

## Next version

v0.2 selects and integrates the Streaming Availability API, maps source
providers to stable WatchPulse keys, and persists region-aware current state and
append-only lifecycle events.
