# WatchPulse v0.2 — Streaming Lifecycle

Released: pending merge

## Outcome

WatchPulse can ingest region/provider-scoped streaming lifecycle changes,
preserve their history, and apply them idempotently to current availability
state without exceeding configured API budgets.

## Delivered

- Movie of the Night Streaming Availability API v4 client and ADR;
- stable Netflix, Disney+, Prime Video, and Apple TV+ provider mappings;
- cursor pagination and subscription-only combined catalog requests;
- new, removed, updated, expiring, and upcoming event support;
- deterministic event identifiers and append-only normalized Parquet history;
- current-state DuckDB application with region/provider isolation;
- per-run and persisted calendar-month request limits;
- local event replay and human-readable inspection commands;
- bounded manually triggered GitHub Actions ingestion with retained artifacts;
- offline fixtures and lifecycle business tests.

The first-release runtime default requests only `new` and `upcoming` (one page
each). Support for the other lifecycle types remains implemented but is not
used by the default MVP workflow.

The manually triggered GitHub workflow combines all four launch subscription
catalogs and fully paginates `new` and `upcoming`, with a 500-request run ceiling
per manual invocation. It is never started by a cron. The 800-request monthly
cap is enforced when the same DuckDB file persists across runs; GitHub-hosted
runner artifacts are not yet durable quota state.

## Validation

- All five lifecycle types returned HTTP 200 for Greece.
- Six total requests were consumed during development validation.
- The successful `new` smoke run persisted 25 events.
- The remaining four-type run persisted and applied 100 events.
- A complete Netflix Greece `new` run reached `hasMore=false` after 11 pages,
  persisted 265 events, and stayed well below its 500-request safety ceiling.
- Ruff, secret detection, compilation, and the complete offline suite pass.

## Known limitations

- Workflow artifacts are retained per run; durable deployed storage is
  introduced with deployment infrastructure.
- Automatic scheduling is intentionally disabled until durable storage,
  monitoring, and an explicit production API budget are in place.
- The API's changes window cannot reconstruct availability older than 31 days;
  TMDB seed reconciliation and v0.3 serving models fill the initial catalog.
- `updated` events only refresh known state because the event alone does not
  safely indicate addition versus removal.
- Only show-level lifecycle events are modeled; season/episode events are later.
